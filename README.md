# 医保合规证据复核台 · 在线演示版（纯静态，无需 Python）

本目录是「AI 医保合规证据定位」Demo 的**纯前端静态版本**，不依赖 Python、不连接任何后端，可直接整目录上传 GitHub 并通过 GitHub Pages 生成在线链接，供客户线上体验。

> 演示的是：银海只给「违规／存疑结论 + 参考条款」，本系统补充**病历证据定位**——把结论追溯到具体文书、具体行、具体字符区间，并在完整病历原文里高亮预览，辅助人工复核。在此基础上，还能针对定位到的问题给出 **AI 修改建议**，支持一键复制、应用到文书或手动编辑，经人工确认后「写回」原始文书。

---

## 核心演示功能

1. **证据定位**：银海结论 → 定位到具体文书、行号、字符区间，原文黄色高亮预览。
2. **AI 修改建议**：定位到有问题的病历／报告后，给出 1～3 条修改建议（含原文、建议改法、理由），每条支持「复制建议」「应用到文书」「定位该行」。
3. **人工编辑**：点击抽屉工具栏的「编辑」可手动修改文书原文，修改的行会标红提示。
4. **人工确认保存**：发生任何修改后，底部「人工确认保存」按钮自动点亮；点击后提示「修改成功：已写回原始《xxx》」，预览同步更新。

## 一、目录结构

```
demo_online/
├── index.html          # 入口页（已内嵌一份演示数据作为离线兜底）
├── app.js              # 前端逻辑（原生 JS，零依赖）
├── style.css           # 样式（纯本地，无 CDN）
├── data/
│   └── ui_data.json    # 演示数据（12 名患者、20 条线索、完整病历文书）
├── .nojekyll           # 让 GitHub Pages 原样服务静态文件，跳过 Jekyll
└── README.md
```

## 二、部署到 GitHub Pages（在线链接）

1. 在 GitHub 新建仓库，把 `demo_online` 目录下的**全部文件**上传到仓库根目录（`index.html` 必须位于根目录）。
2. 进入仓库 **Settings → Pages**：
   - Source 选择 **Deploy from a branch**；
   - Branch 选择 `main`（或你的默认分支），目录选 **/ (root)**；
   - 保存后稍等约 1 分钟，即可得到形如 `https://<用户名>.github.io/<仓库名>/` 的在线链接。
3. 把该链接发给客户即可，手机和电脑浏览器均可直接访问。

> 说明：页面数据通过相对路径 `data/ui_data.json` 读取，因此无论部署在域名根、子路径还是自定义域名下都能正常加载。

## 三、本地预览（可选）

- **在线体验（推荐）**：直接双击 `index.html` 也能打开——页面会自动回退到内嵌的演示数据，顶部会显示「离线模式 · 内置演示数据」。
- **模拟线上环境**：在 `demo_online` 目录下启动任意静态服务器，例如：
  ```bash
  python -m http.server 8080
  ```
  然后浏览器访问 `http://127.0.0.1:8080/`。

## 四、数据与治理说明

- **全合成演示数据**：12 名患者、20 条审核线索均为程序生成，不对应任何真实患者、就诊或结算记录。
- **离线预计算**：本在线版展示的是已固化的审核结论与证据定位结果，**不实时调用大模型、不连接 HIS/EMR/银海接口**。顶部的「离线预计算 · 无实时模型」表示页面为纯静态演示；修改建议为演示数据中预置的示例内容。
- **三态辅助**：`有支持证据` / `有明确反证` / `无法确定`，均定位到原文位置供人工复核，**不自动作出拒付、改自费或改通过的决定**。
- 人工复核状态仅保存在当前页面会话中，不持久化、不写入业务系统。

## 五、更新数据

如需更换演示数据，直接替换 `data/ui_data.json`（保持结构一致），并同步更新 `index.html` 中的内嵌兜底数据即可。数据结构可参考原 Demo 的生成管线（`demo/main.py` + `core/`）。
